# World art source

`make_world_art.py` crops `SourceArt/farm_background_source.png` into the static world background and builds independent transparent sprites. It draws crops and tractor with Pillow, then uses `make_character_sprites.py` to extract animals and farmers from the source sheets. Install the tools with `python -m pip install -r Tools/requirements.txt`, then run `python Tools/make_world_art.py` from the project root. The current character previews are `character_preview.png` and `character_world_preview.png`.

The static landscape source was edited from `SourceArt/farm_source.png` with the built-in image generation tool using this prompt:

> Use case: precise-object-edit. Asset type: STATIC BACKGROUND LAYER for a modular portrait pixel-art farming game. Edit the supplied farm image. Keep the camera angle, overall layout, winding tan paths, green grass, trees, flowers, four rectangular soil beds, fences, chicken shelter, yellow-roof barn, red shed, and sheep pasture fences in place. Remove EVERY changeable gameplay object from the image: all chickens, all sheep, all farmers/workers, all vegetables and fruit/cabbages/carrots/tomatoes, all growing seedlings, and any harvest or tool items. The four crop beds should be clean brown tilled soil with subtle furrows, ready for separate crop sprites to overlay. The animal pens should contain only grass. Keep buildings and environmental props static. Maintain crisp 16-bit pixel-art pixels, dark brown outlines, warm palette. Do not add labels, UI, text, people, animals, crops, or new buildings. Preserve the original image aspect ratio and full composition as closely as possible.

World behavior lives in `Assets/Scripts/World`. `FarmWorldController` places every object, `CropPlot` groups cells, `CropCell` saves growth stages, `WorldActor` saves animal and worker production timers, and `WorldSprite` handles visual art and clicks. `WorldActorAnimator` gives animals and workers separate idle and walking states, short bounded routes, breathing, a step bounce and horizontal turns. Workers show their walking frame only while moving.

`FarmWorldController` starts with one chicken, one sheep and one cow. Each animal upgrade adds one more of each using fixed homes inside the two fenced areas. The sheep and cows use a short roaming radius so their feet stay behind the front fence. `animal_spawn_preview.png` compares the starting arrangement with the first upgrade; `animal_spawn_five_preview.png` shows the crowded pen after four upgrades; `world_grid_preview.png` is a coordinate reference for placing future objects.

For saves created before the one-of-each roster, `FarmGameState` records the current animal upgrade level as a one-time roster baseline. This starts the new visible roster at one of each without changing saved gold or levels. Later animal purchases add one of each, and the new baseline remains stable across restarts.

The animal upgrade starts at 1,000 coins for testing. Existing saves receive that lower price once; later purchases continue to increase and persist the price normally.

The animal sheet at `SourceArt/animals_sheet.png` was generated with the built-in image generation tool in **stylized-concept** mode, using `SourceArt/farm_source.png` as a style reference. Its final prompt was:

> Use case: stylized-concept. Asset type: transparent pixel-art animal sprite sheet for a mobile farming game. Use the supplied farm illustration ONLY as the style reference: match its crisp chunky 16-bit pixels, warm saturated palette, soft 3/4 isometric angle, and dark chocolate-brown pixel outlines. Create exactly FIVE separate full-body animals, all facing slightly to the right, in a neat 3-column by 2-row grid with generously empty gutters: top row = plump ivory chicken with red comb, warm brown hen with red comb, fluffy cream sheep with dark face; bottom row = cool gray sheep with dark face, small black-and-white dairy cow, and leave the sixth cell EMPTY. Each animal should be an individual game sprite with a clear expressive face, tiny highlights, detailed feather/fleece/patch clusters, a small integrated ground shadow, and readable silhouette at 48x48 pixels. Equal scale within species, no touching or overlapping between cells. Genuinely transparent background, no scene, no text, no labels, no frame, no extra objects, no watermark. Preserve strict pixel edges; no painterly blur, no antialiasing, no 3D rendering.

The farmer sheet at `SourceArt/farmers_sheet.png` was generated with the same tool and mode, using the same style reference. Its final prompt was:

> Use case: stylized-concept. Asset type: transparent 16-bit pixel-art farmer sprite sheet for a mobile farming game. Match the supplied farm illustration's dark brown pixel outlines, straw-hat colors, saturated green/brown palette, chunky crisp pixels and slightly elevated 3/4 isometric camera. Create exactly FOUR separate full-body farmer sprites in a clean 2-column by 2-row grid with very wide transparent gutters. Left column: blue-overalls farmer, light blue shirt, straw hat, one hand holding a small watering can. Right column: red-shirt farmer, denim overalls, straw hat, one hand holding a small basket of harvest. Top row: idle standing poses. Bottom row: same two characters in a clear alternate walking step pose, preserving their clothing, faces and size exactly. Every character faces slightly down-right, with expressive eyes, simple hands, a few fabric folds and warm highlights, integrated tiny ground shadow. Keep the silhouette readable at 40x48 game pixels. Each cell must contain only its one character. Genuinely transparent background; no farm scene, no text, no labels, no frame, no extra people or tools outside the hands, no watermark. Strict clean pixel edges, no painterly blur or antialiasing.

The animal sheet contains a vignette despite the transparency request. The extractor removes that background, then scales and hardens the alpha of each sprite. Each worker has a second walking frame, switched by `WorldActor` at runtime.
